# AI Office · этап 3

Самостоятельный локальный пиксельный офис для восьми постоянных работников AI-команды.

## Запуск в Windows

Требуется Node.js 22.14+ (проверено на 24.18) и npm.

Откройте PowerShell в папке проекта:

```powershell
npm install
npm run dev
```

Откройте адрес, напечатанный Vite, обычно http://127.0.0.1:5173.
Также можно дважды нажать `START.cmd`. Остановка — Ctrl+C в открытом окне.

## Что проверить

- В комнате ровно 8 сотрудников; каждый со своим столом, цветом, персонажем и ролью.
- Нажатие на стол или Enter/Space открывает задачу и прогресс справа.
- В карточке каждого сотрудника показаны его основной Skill, краткое описание и ответственность. В раскрывающемся пункте указан подготовленный профиль Codex и граница mock-режима.
- Кнопка «Запустить workflow» создаёт задачу от Lead. Далее каждые 2,6 секунды: Frontend получает и выполняет → QA тестирует → Technical Reviewer проводит независимое ревью → Lead получает и завершает. Все шаги — mock.
- Пауза останавливает события и анимации, продолжение возобновляет их; сброс возвращает исходные данные.
- Вкладка «Задачи» открывает созданные задачи, нажатие возвращает к исполнителю. При старте задач нет, все 8 сотрудников idle.
- В Task Panel можно создать задачу с описанием и приоритетом, назначить сотрудника, запустить, увеличить прогресс, передать на testing/review, завершить или отметить failed. Во время workflow ручные изменения заблокированы. Если участник занят другой задачей, запуск workflow отклоняется без создания лишней задачи.
- Activity можно фильтровать по сотруднику или ошибкам.
- На телефоне сцена прокручивается вбок, панели расположены ниже.

При перезагрузке состояние начинается заново. Данные не сохраняются. Сброс очищает задачи и журнал. Одному сотруднику можно назначить только одну незакрытую задачу, включая pending. Testing передаёт задачу QA; review по умолчанию — Technical Reviewer. Предыдущий исполнитель освобождается. Completed и failed закрывают задачу и запрещают её изменение. После закрытия сотрудник может получить следующую задачу. Счётчик активных включает working, thinking, reviewing и testing. Журнал хранит последние 80 событий, в интерфейсе — до 20 по выбранному фильтру.

## Codex

Это mock-режим: офис не подключён к реальным сессиям Codex. Внутренний интерфейс CodexAdapter и MockCodexAdapter имеют общий контракт. Это не API Codex. Архитектура этапа 2 и исследование этапа 1: ARCHITECTURE.md. Реальная интеграция — отдельный будущий этап после проверки официальной документации.

Этап 3 добавляет проектные инструкции в `.agents/skills/` и профили в `.codex/agents/`. Для обнаружения откройте корень AI Office в Codex. Полная команда, вызов и поддержка: [TEAM_STRUCTURE](docs/TEAM_STRUCTURE.md), [AGENT_SKILLS](docs/AGENT_SKILLS.md), [AGENT_PROFILES](docs/AGENT_PROFILES.md).
