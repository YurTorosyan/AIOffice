# AI Office · Stage 4B

Самостоятельный локальный пиксельный офис для восьми постоянных работников AI-команды.

## Запуск в Windows

Требуется Node.js 22.14+ (проверено на 24.18) и npm.

Откройте PowerShell в папке проекта:

```powershell
npm install
npm run dev
```

Откройте адрес, напечатанный Vite, обычно http://127.0.0.1:5173.
Также можно дважды нажать `START.cmd`. Остановка — Ctrl+C в открытом окне.

## Что проверить

- В комнате ровно 8 сотрудников; каждый со своим столом, цветом, персонажем и ролью.
- Нажатие на стол или Enter/Space открывает задачу и прогресс справа.
- В карточке каждого сотрудника показаны назначенные community Skills, их статусы и ответственность. Источник, лицензия, commit и ограничения доступны в раскрывающихся подробностях. Installed подтверждён файлами и контрольными суммами, а не только записью в реестре.
- Кнопка «Запустить workflow» создаёт задачу от Lead. Далее каждые 2,6 секунды: Frontend получает и выполняет → QA тестирует → Technical Reviewer проводит независимое ревью → Lead получает и завершает. Все шаги — mock.
- Пауза останавливает события и анимации, продолжение возобновляет их; сброс возвращает исходные данные.
- Вкладка «Задачи» открывает созданные задачи, нажатие возвращает к исполнителю. При старте задач нет, все 8 сотрудников idle.
- В Task Panel можно создать задачу с описанием и приоритетом, назначить сотрудника, запустить, увеличить прогресс, передать на testing/review, завершить или отметить failed. Во время workflow ручные изменения заблокированы. Если участник занят другой задачей, запуск workflow отклоняется без создания лишней задачи.
- Activity можно фильтровать по сотруднику или ошибкам.
- На телефоне сцена прокручивается вбок, панели расположены ниже.

При перезагрузке состояние начинается заново. Данные не сохраняются. Сброс очищает задачи и журнал. Одному сотруднику можно назначить только одну незакрытую задачу, включая pending. Testing передаёт задачу QA; review по умолчанию — Technical Reviewer. Предыдущий исполнитель освобождается. Completed и failed закрывают задачу и запрещают её изменение. После закрытия сотрудник может получить следующую задачу. Счётчик активных включает working, thinking, reviewing и testing. Журнал хранит последние 80 событий, в интерфейсе — до 20 по выбранному фильтру.

## Pause, Checkpoint & Resume — Stage 4B

В Task Panel доступны «Пауза задачи», «Возобновить задачу», «Сохранить checkpoint» и «Где остановились». Команда «Продолжим работу» выбирает единственную возобновляемую задачу; если их несколько, требуется выбор. В реальном режиме Pause ждёт подтверждения interruption от Codex; общая пауза анимации — отдельная кнопка.

Реальные checkpoints хранятся в игнорируемой `.ai-office/recovery.json` и переживают перезапуск моста. Mock использует отдельный localStorage. После перезапуска выполнение само не начинается. Completed/failed не возобновляются. Только Lead подключён к Codex; запись и другие сотрудники не разрешены. Никаких таймаутов вместо обнаружения лимита.

Подробности формата, безопасности, восстановления исходного потока и fallback: [CHECKPOINTS](docs/CHECKPOINTS.md). Результаты этапа: [STAGE4B-REPORT](STAGE4B-REPORT.md).

## Codex

Стартовый режим — mock. Для реального read-only pilot только Lead Developer нужен установленный Codex CLI 0.144.5 и существующий вход через `codex login`. В обычном PowerShell пользователя выполните:

```powershell
npm run build
npm run bridge
```

Откройте http://127.0.0.1:8787, выберите «Codex pilot →», «Подключить», «Задание на чтение». Остальные семь сотрудников не подключаются. Возврат в mock закрывает подключение; перезагрузка страницы сама по себе не останавливает runtime. Остановка bridge — Ctrl+C. После изменений server-кода мост нужно перезапустить.

Протокол, sandbox/approval boundaries и ограничения: [CODEX_RUNTIME](docs/CODEX_RUNTIME.md). Фактические результаты проверки: [STAGE4A-REPORT](STAGE4A-REPORT.md). Внутренний CodexAdapter — контракт AI Office, а не выдуманный API Codex.

Stage 3B устанавливает 12 реальных community Skills в `.agents/skills/`; восемь профилей в `.codex/agents/` сохранены. Три дополнительных кандидата явно не установлены. Для обнаружения откройте корень AI Office в Codex и начните новый ход/сессию. Полный каталог, лицензии, источники, ограничения и версии: [COMMUNITY_SKILLS_CATALOG](docs/COMMUNITY_SKILLS_CATALOG.md). Команда и поддержка: [TEAM_STRUCTURE](docs/TEAM_STRUCTURE.md), [AGENT_SKILLS](docs/AGENT_SKILLS.md), [AGENT_PROFILES](docs/AGENT_PROFILES.md).

Перед запуском и build проверяются физические файлы. После изменения файлов Skills перезапустите dev или пересоберите production. Примеры webapp-testing требуют отдельно Python Playwright/browser binaries; они не устанавливались и не выполнялись. Исходные custom-written Skills этапа 3 сохранены в docs/legacy-agent-skills. На Stage 3B профили не запускались; Stage 4A проверяет отдельно только Lead.
