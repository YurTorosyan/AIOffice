# S01–S36 acceptance trace

Scope: deterministic contracts, real local filesystem effects in artificial workspaces, controlled RPC, fake container-command adapters and a fresh browser. No real model turn or active project is used. See the final counts and log hashes in [report](STABILIZATION_REPORT.md). A mock product result is not a real project QA receipt.

Each row identifies a reproduced condition and checked assertion, not just a filename. Existing regression cases are retained. Controlled crash artifacts, full states, receipts, mtimes/hashes and slot traces are generated under ignored `work/p0-validation` and `work/stabilization-matrix`; browser artifacts are under `work/stabilization-browser`.

## Repetition and evidence limits

`p0-crash-matrix` runs seven real process-exit windows × ten deterministic inputs = 70 cases per full suite. Separate ten-case tests exercise lost effect acknowledgement (S14), start intent/acknowledgement (S21), pre-tick archival (S22), and flush/publication failures (S23). Artifacts preserve phase, IDs, per-resource observations and receipts; before/after file mtimes are asserted, not inferred from a PASS label.

Both full suite configurations run the dedicated complete-graph slot scenarios for 1 and 2 explicitly. Some regression fixtures intentionally fix two slots to test parallel behavior; setting the environment to 1 does not turn those fixtures into one-slot tests. The report distinguishes employee execution slots from the test runner's two-file concurrency.

Not covered by these simulations: physical power loss/storage hardware guarantees; live provider outage/cost/quota behavior; arbitrary framework/browser acceptance contracts; unrestricted natural-language specification correctness; operation migration without sufficient historical ownership evidence. Those are not silently counted as passing P4 or deployed production checks.
