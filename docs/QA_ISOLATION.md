# Stage 7 completion — isolated QA tests

QA now has a narrowly registered `node_tests` executor. Other terminal profiles, dependencies, network and Git mutations remain blocked. Codex tools and privileges are unchanged. No Codex tasks were started during implementation or verification.

## Runtime

Docker Desktop's already-installed local Linux engine is used. The image is the official `docker.io/library/node:24.18.0-bookworm-slim`, pinned in `server/qa-image.json` to `node@sha256:6f7b03f7c2c8e2e784dcf9295400527b9b1270fd37b7e9a7285cf83b6951452d`. It was explicitly downloaded during setup. The bridge never downloads or builds images automatically and never executes package install scripts. Runtime uses the fixed local Docker socket/pipe; environment variables cannot redirect snapshots to a remote engine.

The container receives only the exact task-scoped, permission-checked source snapshots over stdin, plus a fixed generated `{type:"module"}` package manifest. **No project/workspace, host directory, credential store or Docker socket is mounted.** The host environment is not copied into the container. Imported project files must be included in the task's exact scope. External packages and browser tests are not provisioned; there is no implicit dependency installation or broadening of scope.

Containers run as UID/GID 1000, without capabilities or privilege escalation, with network disabled, read-only image filesystem, private IPC, writable bounded tmpfs for `/work` and `/tmp`, 256 MB memory/swap ceiling, one CPU, 64-process limit, bounded file/output size and 30-second wall-clock timeout. No shell command string is constructed from employee input. A fixed bootstrap invokes Node on the validated file list. Container identity is generated by the broker; cleanup targets only that UUID, never unrelated containers.

At startup a trusted isolation self-check verifies the Linux engine, resource/ seccomp support and installed pinned image, then tests UID, effective capabilities, no-new-privileges, read-only root, absent host/socket/environment and denied network egress. Failure leaves QA blocked. This self-check is an application health check, not an agent task or Codex model request.

## Approval and receipts

Only QA can use this registered terminal executor. Stage 7 still requires a durable, expiring, one-use approval for the exact task/employee/workflow/test command and source revision. Existing workflow diff/test approval controls are reused. Sources are read through the same permission authority; before/after revision checks detect changed host files. A second approval call can return a completed matching receipt without repeating the test. Interrupted/unconfirmed runs are never silently retried.

Node exit zero produces PASS; a test-process failure produces FAIL. Missing isolation, unsupported input, timeout, output overflow or unconfirmed cleanup produces BLOCKED. Browser acceptance remains BLOCKED without real browser evidence. A PASS is evidence that the approved command exited successfully, not proof that employee-written tests are sufficient or that a malicious test cannot exit early. Independent QA/review still assesses their contents.

## Verification

`node --experimental-strip-types scripts/verify-qa-isolation.mjs` performs actual local Docker checks without Codex: isolation self-check; a fixture with an imported TypeScript source; exact Director approval/consumption and saved receipt replay; real failing test; infinite-loop timeout and container cleanup; unchanged host source. The fixture lives under ignored `work/qa-isolation`; the running production workflow/history is not edited. `docs/QA_ISOLATION_EVIDENCE.json` records the result. Unit tests cover the immutable container profile, malformed/unscoped/secret input, failed engine/security/image/cleanup, and PASS/FAIL/BLOCKED distinctions.

Official references: [Docker run controls](https://docs.docker.com/reference/cli/docker/container/run/) and [Docker default seccomp](https://docs.docker.com/engine/security/seccomp/). Container isolation depends on the trusted local Docker installation/kernel and pinned image; it is not a guarantee against a compromised host administrator or container-runtime vulnerability. Do not disable seccomp, add host mounts/network or grant privileged mode to work around failures.

The production bridge must reload this code before its security snapshot reports `executors.qaTests.available: true`. Read-only inspection of a separate preview is not presented as activation of the protected production process. Stage 8 was explicitly queued by the Director and begins only after this completion is committed.
