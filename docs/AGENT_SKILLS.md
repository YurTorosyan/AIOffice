# Agent Skills — этап 3

В AI Office ровно восемь работников и восемь основных Skills. Все инструкции оригинальные, написаны для этого проекта; сторонние Skills и код не устанавливались. Источник соответствий — `src/agents/registry.json`; проверка и доступ — `src/agents/registry.ts`.

| ID работника | Роль | Основной Skill / директория | Явное обращение в Codex |
|---|---|---|---|
| lead | Lead Developer | project-architecture | `$project-architecture` — спланируй изменение и задачи |
| design | UI/UX Designer | ui-ux-design | `$ui-ux-design` — опиши взаимодействия и состояния |
| frontend | Frontend Developer | frontend-engineering | `$frontend-engineering` — реализуй согласованную спецификацию |
| backend | Backend Developer | backend-engineering | `$backend-engineering` — проверь контракт и необходимость backend |
| seo | SEO Specialist | technical-seo | `$technical-seo` — проверь метаданные локального приложения |
| security | Security Engineer | security-audit | `$security-audit` — оцени границы доверия и риски |
| qa | QA Engineer | quality-assurance | `$quality-assurance` — проверь сценарии и регрессии |
| review | Technical Reviewer | independent-code-review | `$independent-code-review` — независимо проверь готовый diff |

Каждая директория находится в `.agents/skills/<skill-id>/` и содержит `SKILL.md`: YAML-поля `name` и `description`, область ответственности, пошаговый процесс, ожидаемый результат, checklist и границы. Имя в YAML совпадает с директорией и registry ID. Текст описания для выбора Skill в Codex ориентирован на условия применения; короткое описание в UI ориентировано на владельца офиса.

## Использование в Codex

Откройте **корень AI Office** как проект/рабочую папку Codex. Эта папка вложена в исходную папку чата: запуск из родительской папки сам по себе не гарантирует обнаружение вложенных Skills. Репозиторные Skills обнаруживаются через `.agents/skills`; в CLI/IDE их можно выбрать через `/skills` или `$имя`, а также описать соответствующую задачу обычным текстом. Если список не обновился, перезапустите Codex. Это соответствует [официальной документации Skills](https://learn.chatgpt.com/docs/build-skills).

Skill задаёт процесс, но не создаёт сотрудника и не запускает агента. Skills доступны на уровне проекта всем профилям; основной Skill закреплён явной ссылкой в developer_instructions каждого профиля. Это не эксклюзивное назначение средствами Codex. Дополнительный контекст не даёт права менять чужую область ответственности.

## Поддержка и проверка

1. Меняйте процедуру соответствующего `SKILL.md`, сохраняя точный ID и конкретные условия выбора.
2. При изменении пользовательского описания меняйте единственную запись `skills` в `src/agents/registry.json`.
3. Обновляйте профиль, если изменились его обязанности или путь к Skill; добавляйте содержательный тест для новой границы поведения.
4. Проверьте YAML/TOML и связи: `npm run validate:agents`; затем `npm test` и `npm run build`.
5. Проверьте карточки сотрудников в браузере; фиксируйте изменения документации и кода одним коммитом.

Для полной проверки формата нужны Python 3.11+ и PyYAML. Зависимость используется только для разработки, не входит в веб-приложение:

```powershell
python -m pip install --target work/validation-deps "PyYAML>=6,<7"
npm run validate:agents
npm test
npm run build
```

`work/` игнорируется Git. TOML проверяется стандартным `tomllib`; YAML — полноценным SafeLoader с запретом повторяющихся ключей. Тесты отдельно проверяют отсутствующие файлы, неверные ссылки профиля и синтаксические ошибки. Проверка структуры не доказывает качество решений реального агента; на этапе 3 профили не запускались.

## Будущий Skill без нарушения связей

На этом этапе девятый основной Skill не допускается. Для уточнения существующего Skill редактируйте его инструкции, сохраняя ID. Для согласованной замены основного Skill выполняйте миграцию одной связки: определение Skill, employee.skillId, customAgent.skillId, путь и ссылка в TOML, ожидаемое соответствие в тестах и документация; остальные семь связок не меняются.

Если Director в будущем разрешит дополнительный вспомогательный Skill, сначала расширьте модель и валидатор отдельным каталогом supporting Skills. Сохраните восемь основных назначений и не создавайте нового сотрудника. Новый Skill должен получить уникальное имя и ограниченный trigger; профиль должен объяснить, когда читать его в помощь основному. Текущий валидатор намеренно отклонит незарегистрированный девятый Skill: такое расширение относится к будущему согласованному этапу.
